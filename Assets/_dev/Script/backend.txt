  왜 itemId만 서버에 넘기는가                                                                                                                                                                                                                                       
  ❌ 나쁜 방식: client → server "HP를 100 올려줘"                                                                                                                                                                                                                
     → 패킷 변조로 9999 보낼 수 있음                                                                                                                                                                                                                             
                                                                                                                                                                                                                                                                 
  ✅ 좋은 방식: client → server "아이템 201번 사용했어"
     → 서버가 DB에서 201번 효과 직접 조회 → 적용

  클라이언트는 의도만 전달하고, 서버가 결과를 결정하는 서버 권위(Server-Authoritative) 패턴이에요.

  ---
  백엔드에서 만들어야 할 엔드포인트

  ┌───────────────────────────┬───────────────────────────────────────────────────────────────────────────┐
  │        엔드포인트         │                             서버가 해야 할 일                             │
  ├───────────────────────────┼───────────────────────────────────────────────────────────────────────────┤
  │ POST /inventory/equip     │ 보유 확인 → 기존 슬롯 장착 해제 → equipped_items upsert → items 수량 감소 │
  ├───────────────────────────┼───────────────────────────────────────────────────────────────────────────┤
  │ POST /inventory/unequip   │ equipped_items에서 itemId 찾기 → 레코드 삭제 → items 수량 복원            │
  ├───────────────────────────┼───────────────────────────────────────────────────────────────────────────┤
  │ POST /inventory/use       │ 보유 확인 → items_table에서 effect 조회 → 효과 적용 → 수량 감소           │
  ├───────────────────────────┼───────────────────────────────────────────────────────────────────────────┤
  │ POST /inventory/discard   │ 보유 확인 → items 수량 amount 감소                                        │
  ├───────────────────────────┼───────────────────────────────────────────────────────────────────────────┤
  │ POST /inventory/transcend │ 조각 보유 확인 → shard_amount 차감 → enhance +1                           │
  └───────────────────────────┴───────────────────────────────────────────────────────────────────────────┘

  모든 응답 형식은 동일하게:
  { "success": true, "user": { ...PlayerData.Apply()에 넘기는 전체 유저 데이터... } }

  클라이언트 흐름 (장착 기준)

  드래그 드롭
    → 로컬 즉시 반영 (낙관적 업데이트, UI 반응성)

    → 서버 응답 → ApplyUserData() → 서버 기준으로 최종 동기화
