## 1️⃣ 수류탄 조준 인디케이터 (GrenadeAimIndicator)

### ✅ 결과

Q 홀드 → 착탄점(노란 원) + 폭발 범위(빨간 채워진 disc + 테두리) 표시, Q 릴리즈 → 해당 위치로 발사

### 📌 수행 이유

수류탄형 스킬은 Directional이 아닌 TargetPoint 방식이므로 착탄 위치를 미리 시각화해야 함

### 📝 작업 내용

- `PlayerCombat.HandleSkillDown()` → `weapon.IsTargetPointSkill(slot)` 이면 `aimIndicator.BeginAim()` 호출
- `PlayerCombat.HandleSkillReleased()` → `aimIndicator.IsActive` 이면 `aimIndicator.TargetPos` 로 발사
- 인디케이터 = 착탄점 LineRenderer + 폭발 범위 disc 메시 + 테두리 LineRenderer

### ⚠️ 트러블슈팅

- **문제 :** Dedicated Server 빌드에서 `Shader.Find()` null → `ArgumentNullException` 크래시
    - **원인 :** `PlayerCombat.Awake()`가 서버에서도 실행 → Dedicated Server는 셰이더 없음
    - **해결 :** GrenadeAimIndicator 생성을 `Awake()` → `OnStartLocalPlayer()` 로 이동 (로컬 플레이어 클라이언트에서만 실행)

    **🧠 내가 이해한 원리 :**
    Mirror에서 `Awake()`는 서버/클라이언트 모두 실행되지만, `OnStartLocalPlayer()`는 해당 플레이어를 소유한 클라이언트에서만 호출된다. 셰이더·렌더링 관련 코드는 반드시 클라이언트 전용 콜백에 넣어야 한다.

- **문제 :** Quad primitive 생성 직후 `Destroy(col)` → `Concave MeshCollider` 경고
    - **원인 :** `Destroy()`는 프레임 끝에 처리되어 같은 프레임 물리 시스템이 먼저 검사
    - **해결 :** `DestroyImmediate(col)` 로 즉시 제거

- **문제 :** `Universal Render Pipeline/Unlit` 셰이더를 코드로 세팅하면 투명도가 적용 안 됨
    - **원인 :** URP 머티리얼은 키워드·프로퍼티를 정확히 설정해야 하고, URP 버전마다 셰이더 이름이 다를 수 있음
    - **해결 :** `Sprites/Default` 셰이더 사용 (Unity 내장, 모든 파이프라인 동작, vertex color + alpha 지원)

### 💻 주요 코드 스니펫

**🔹 목적: 서버에서 인디케이터 생성 방지**

```csharp
// PlayerCombat.cs
private void Awake()
{
    weapon = GetComponent<CharacterWeapon>();
    // 인디케이터 생성 없음 — OnStartLocalPlayer에서 처리
}

public override void OnStartLocalPlayer()
{
    aimIndicator = GetComponentInChildren<GrenadeAimIndicator>();
    if (aimIndicator == null)
    {
        var go = new GameObject("GrenadeAimIndicator");
        go.transform.SetParent(transform);
        go.transform.localPosition = Vector3.zero;
        aimIndicator = go.AddComponent<GrenadeAimIndicator>();
    }
}
```

📌 **사용 이유 :** `OnStartLocalPlayer()`는 로컬 클라이언트에서만 실행 → 서버는 절대 진입 안 함

📌 **주의할 점 :** `HandleSkillDown`에서 `aimIndicator == null` 체크 필수 (OnStartLocalPlayer 이전 호출 방어)

**🔹 목적: LineRenderer + 절차적 disc 메시로 인디케이터 렌더링**

```csharp
// 착탄점: LineRenderer 원
private LineRenderer CreateLineCircle(string goName, float width, Color color)
{
    var lr = go.AddComponent<LineRenderer>();
    lr.useWorldSpace = true;
    lr.loop = true;
    lr.material = new Material(Shader.Find("Sprites/Default"));
    return lr;
}

// 폭발 범위: 절차적 원형 메시 (XZ 평면)
private static Mesh BuildDiscMesh(int segs)
{
    var verts = new Vector3[segs + 1];
    verts[0] = Vector3.zero;
    for (int i = 0; i < segs; i++)
    {
        float angle = i * Mathf.PI * 2f / segs;
        verts[i + 1] = new Vector3(Mathf.Cos(angle) * 0.5f, 0f, Mathf.Sin(angle) * 0.5f);
    }
    // 삼각형 구성 후 RecalculateNormals()
}
```

📌 **사용 이유 :** `Sprites/Default`는 vertex color와 alpha를 지원하며 URP/Standard 모두에서 확실히 동작함

## 2️⃣ 폭발 위치 버그 수정 (rb.MovePosition vs transform.position)

### ✅ 결과

수류탄이 조준 위치에서 정확히 폭발 (이전: 항상 스폰 위치에서 폭발)

### 📌 수행 이유

폭발 이펙트와 데미지 판정이 목표 위치가 아닌 플레이어 발밑에서 발생하는 심각한 버그

### 📝 작업 내용

`MoveArc()` 의 포물선 이동 종료 시점(t ≥ 1)에서 `transform.position`으로 폭발 위치를 결정하는 구조였는데, 이 시점의 `transform.position`이 실제 목표 위치가 아니라 이전 프레임 위치였음

### ⚠️ 트러블슈팅

- **문제 :** 폭발이 항상 스폰 위치(플레이어 발밑)에서 발생
    - **원인 :** `rb.MovePosition(nextPos)` / `rb.position = nextPos` 는 FixedUpdate 내에서 `transform.position` 에 즉시 반영되지 않음. Unity 물리 엔진은 FixedUpdate가 끝난 후에야 physics position → transform 동기화를 수행함. 따라서 같은 FixedUpdate 내에서 `Explode()`를 호출하면 `transform.position`은 여전히 이전 프레임 값(=스폰 위치)
    - **해결 :** `rb.position = nextPos` 대신 `transform.position = nextPos` 사용 → transform 직접 설정은 즉시 반영됨

    **🧠 내가 이해한 원리 :**
    Unity Physics에서 위치를 업데이트하는 방법은 3가지이며 반영 시점이 다르다:
    
    | 방법 | transform.position 반영 |
    |------|------------------------|
    | `rb.MovePosition(pos)` | FixedUpdate 끝 (물리 스텝 후) |
    | `rb.position = pos` | FixedUpdate 끝 (물리 스텝 후) |
    | `transform.position = pos` | **즉시** |
    
    Kinematic Rigidbody를 이동시키는 올바른 방법은 `rb.MovePosition`이지만, 같은 프레임에 transform을 읽어야 할 때는 `transform.position`으로 직접 설정해야 한다.

### 💻 주요 코드 스니펫

**🔹 목적: 포물선 종료 시 정확한 위치에서 폭발**

```csharp
// ExplosiveProjectile.cs - MoveArc()
if (t >= 1f)
{
    // rb.position = nextPos → FixedUpdate 내에서 transform.position 미반영 (버그)
    // transform.position = nextPos → 즉시 반영 (정상)
    transform.position = nextPos;
    Explode();
    DestroySelf();
}
else
{
    rb.MovePosition(nextPos);
}
```

📌 **사용 이유 :** `Explode()` 내부에서 `transform.position`으로 OverlapSphere 위치 결정

📌 **주의할 점 :** 비행 중간 프레임에는 `rb.MovePosition` 유지 (물리적으로 올바른 방법). 마지막 프레임(t≥1)에서만 `transform.position` 직접 설정

## 3️⃣ 외벽 레이어 자동 설정 (MapWallGenerator)

### ✅ 결과

인스펙터에서 `wallLayerName = "Wall"` 설정 후 재생성해도 레이어 유지

### 📌 수행 이유

`[ExecuteAlways]`로 OnValidate에서 재생성 시 컨테이너가 Default 레이어로 초기화되어 매번 수동으로 레이어를 다시 설정해야 했음

### 📝 작업 내용

`CreateContainer()` 에 `layer` 파라미터 추가, `LayerMask.NameToLayer(wallLayerName)` 로 생성 시 자동 적용

### 💻 주요 코드 스니펫

**🔹 목적: 벽 컨테이너 생성 시 레이어 자동 설정**

```csharp
// MapWallGenerator.cs
[SerializeField] private string wallLayerName = "Wall";

private Transform CreateContainer(string containerName, int layer = 0)
{
    var go = new GameObject(containerName);
    go.layer = layer;  // 생성 시 즉시 레이어 설정
    go.transform.SetParent(transform);
    ...
}

// SpawnWalls()에서
int wallLayer = LayerMask.NameToLayer(wallLayerName);
var front = CreateContainer("Wall_Front", wallLayer);
```

📌 **사용 이유 :** BoxCollider가 컨테이너에 붙어있으므로 컨테이너의 레이어가 물리 판정에 사용됨

📌 **주의할 점 :** Project Settings > Tags & Layers에 "Wall" 레이어가 등록되어 있어야 함

## 🧠 오늘 배운 점

- `rb.MovePosition()` / `rb.position` 은 FixedUpdate 내에서 `transform.position` 에 즉시 반영되지 않는다. 같은 프레임에 transform을 읽어야 할 때는 `transform.position = pos` 를 직접 사용해야 한다.
- Mirror에서 셰이더·카메라·마우스 등 클라이언트 전용 코드는 반드시 `OnStartLocalPlayer()` 에 넣어야 한다. `Awake()`는 서버에서도 실행된다.
- Unity `Sprites/Default` 셰이더는 모든 렌더 파이프라인(Standard/URP)에서 동작하며, vertex color와 alpha 투명도를 기본 지원한다. 코드로 머티리얼을 생성할 때 URP Unlit보다 훨씬 안정적이다.
- SyncVar 훅은 클라이언트에서만 호출된다 (서버에서 SyncVar를 설정해도 서버 측 훅은 실행되지 않음).
