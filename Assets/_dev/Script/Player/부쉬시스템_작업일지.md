## 1️⃣ BushZone + PlayerBushState 구현

### ✅ 결과

`BushZone`(부쉬 영역)과 `PlayerBushState`(플레이어 가시성 상태) 컴포넌트 신규 작성

### 📌 수행 이유

부쉬 안팎 가시성 판단은 서버 권위 + 클라이언트 렌더링 분리가 필요했음.
서버에서 inBush/isRevealed SyncVar 를 관리하고 클라이언트가 렌더러 On/Off를 처리하는 구조.

### 📝 작업 내용

- `BushZone.cs` — OnTriggerEnter/Exit로 플레이어 진입 감지, `teamVisionMask` SyncVar 로 팀 시야 비트 관리
- `PlayerBushState.cs` — `inBush` / `isRevealed` / `currentBushIdentity` SyncVar 3종, 0.5초 진입 딜레이 코루틴, 1초 RevealTemporarily 코루틴

**가시성 판단 우선순위 (IsVisibleToLocalPlayer)**

```
1. isLocalPlayer → 자기 자신은 항상 보임
2. !inBush       → 부쉬 밖이면 항상 보임
3. isRevealed    → 공격 직후 노출 중
4. 같은 팀       → 팀원은 항상 보임
5. currentBush.HasTeamVision(local.teamId)
                 → 내 팀원이 이 부쉬에 있으면 보임
```

### ⚠️ 트러블슈팅

- **문제:** 팀원이 부쉬에 들어와도 그 안의 적이 보이지 않을 수 있음
    - **원인:** `teamVisionMask`(BushZone SyncVar)가 바뀌어도 이미 부쉬 안에 있는 적의 `PlayerBushState`는 가시성 재계산을 하지 않음
    - **해결 방법:** `PlayerBushState`가 `currentBushIdentity` 변경 시 BushZone의 `OnVisionMaskChanged` 이벤트를 구독. 마스크가 바뀔 때마다 `UpdateVisibility()` 자동 호출

    **🧠 내가 이해한 원리:**
    SyncVar hook은 자기 오브젝트의 값 변화만 감지한다. 다른 오브젝트(BushZone)의 SyncVar 변화에 반응하려면 C# event를 통해 직접 연결해야 한다.

- **문제:** `inBush` hook이 먼저 실행될 때 `currentBushIdentity`가 아직 null일 수 있음
    - **원인:** Mirror는 SyncVar를 선언 순서대로 직렬화하고 역직렬화하면서 hook을 즉시 호출함. `inBush`(1번)의 hook이 실행될 때 `currentBushIdentity`(3번)가 아직 역직렬화 전일 수 있음
    - **해결 방법:** `currentBushIdentity`에도 hook을 추가해 값이 들어오면 `UpdateVisibility()` 재호출

    **🧠 내가 이해한 원리:**
    Mirror SyncVar 역직렬화는 선언 순서대로 하나씩 값을 세팅하고 hook을 즉시 실행한다. 한 프레임의 여러 SyncVar 변경이 "동시에" 도착해도 클라이언트 입장에선 순서가 있다.

### 💻 주요 코드 스니펫

**🔹 목적: 팀 시야 비트마스크 관리**

```csharp
// BushZone.cs
public bool HasTeamVision(int teamId) => (teamVisionMask & (1 << teamId)) != 0;

// 팀원 진입
teamVisionMask |= (1 << team);

// 팀원 전원 퇴장
if (!HasAnyPlayerOfTeam(team))
    teamVisionMask &= ~(1 << team);
```

📌 **사용 이유:** int 하나로 최대 32팀의 시야 여부를 표현. SyncVar 1개로 모든 팀 상태 동기화 가능.

📌 **주의할 점:** teamId가 32 이상이면 비트 오버플로우. 현재 2팀 구조에선 문제 없음.

---

**🔹 목적: BushZone 이벤트 구독/해제 (메모리 누수 방지)**

```csharp
// PlayerBushState.cs — OnCurrentBushChanged hook
private void OnCurrentBushChanged(NetworkIdentity oldBush, NetworkIdentity newBush)
{
    if (_subscribedBush != null)
        _subscribedBush.OnVisionMaskChanged -= UpdateVisibility;

    _subscribedBush = newBush?.GetComponent<BushZone>();

    if (_subscribedBush != null)
        _subscribedBush.OnVisionMaskChanged += UpdateVisibility;

    UpdateVisibility();
}

private void OnDestroy()
{
    if (_subscribedBush != null)
        _subscribedBush.OnVisionMaskChanged -= UpdateVisibility;
}
```

📌 **사용 이유:** 부쉬를 옮겨 다닐 때 이전 부쉬 이벤트를 반드시 해제해야 중복 호출 방지.

📌 **주의할 점:** `OnDestroy`에서 해제 안 하면 오브젝트 삭제 후에도 이벤트가 남아 NullReferenceException 발생.

## 2️⃣ DamagePopup + DamagePopupManager 구현

### ✅ 결과

피격 시 서버에서 ClientRpc로 모든 클라이언트에 팝업 위치·수치를 전달, 각 클라이언트가 로컬로 스폰

### 📌 수행 이유

데미지 표시는 순수 시각 피드백이므로 네트워크 오브젝트가 아닌 로컬 스폰으로 처리. 부쉬 안에서 피격당해도 숨겨진 채로 데미지 숫자만 표시하는 규칙 반영.

### 📝 작업 내용

- `DamagePopup.cs` — TextMeshPro(3D), 위로 떠오르며 페이드아웃, 카메라 방향 자동 회전
- `DamagePopupManager.cs` — 싱글턴, 프리팹 인스턴스화
- `PlayerStats.TakeDamage` 에 `RpcShowDamagePopup(actualDamage, position)` 추가

### ⚠️ 트러블슈팅

- **문제:** 부쉬 안 적이 피격당할 때 위치가 노출되지 않는가?
    - **원인:** 팝업이 피격자 `transform.position + Vector3.up * 1.5f` 위치에 뜸 → 위치가 대략 노출됨
    - **해결 방법:** 브롤스타즈 방식과 동일하게 의도적으로 허용. 정확한 위치가 아닌 "이 근처에 누군가 있다" 정도의 힌트는 게임플레이상 허용 범위.

    **🧠 내가 이해한 원리:**
    완전한 위치 은폐보다 "데미지를 입혔다는 피드백"이 게임플레이에 더 중요. 브롤스타즈도 동일한 설계.

### 💻 주요 코드 스니펫

**🔹 목적: 서버에서 클라이언트 전체에 팝업 트리거**

```csharp
// PlayerStats.cs
[Server]
public void TakeDamage(DamageInfo info)
{
    float actualDamage = Mathf.Max(1f, info.Amount - defense);
    currentHp -= actualDamage;

    RpcShowDamagePopup(actualDamage, transform.position + Vector3.up * 1.5f);
    // ... 나머지 로직
}

[ClientRpc]
private void RpcShowDamagePopup(float amount, Vector3 worldPos)
{
    DamagePopupManager.Instance?.Show(amount, worldPos);
}
```

📌 **사용 이유:** 데미지 수치 계산은 서버에서만 일어나므로 ClientRpc로 결과값을 전달. 팝업 오브젝트 자체는 NetworkServer.Spawn 없이 각 클라이언트에서 로컬 Instantiate.

📌 **주의할 점:** DamagePopupManager가 씬에 없으면 `Instance`가 null → 팝업 미표시. 배틀씬에 반드시 배치할 것.

## 3️⃣ 기존 시스템 연동

### ✅ 결과

CharacterWeapon(근접/대시), ProjectileBase(투사체), BattleNetworkPlayer(teamId), CharacterSpawner(렌더러 캐싱), PlayerHPBar(HP바 토글) 연동 완료

### 📌 수행 이유

공격 성공 판정은 이미 각 공격 타입 클래스에서 일어나고 있으므로, 그 지점에 Reveal 호출만 추가하면 됨.

### 📝 작업 내용

| 파일 | 변경 내용 |
|---|---|
| `BattleNetworkPlayer` | `teamId` SyncVar + `s_teamCounter` 자동 부여 |
| `CharacterSpawner` | SpawnVisual 후 `PlayerBushState.CacheRenderers` 호출 |
| `CharacterWeapon` | PerformMelee / DashDamageAfterDelay 명중 시 `RevealTemporarily` |
| `ProjectileBase` | OnHit 후 owner의 `RevealTemporarily` |
| `PlayerHPBar` | `SetBushVisible(bool)` — HP바 캔버스 SetActive |

### ⚠️ 트러블슈팅

- **문제:** 새 매치 시작 시 teamId가 이전 게임에서 이어서 증가할 수 있음
    - **원인:** `s_teamCounter`가 static 변수라 씬 전환 후에도 유지됨
    - **해결 방법:** 매치 시작 지점에서 `BattleNetworkPlayer.ResetTeamCounter()` 호출 필요 (미완료 — 다음 할 일)

    **🧠 내가 이해한 원리:**
    static 변수는 씬 전환으로 초기화되지 않는다. 게임 상태를 관리하는 매니저에서 명시적으로 리셋해야 한다.

### 💻 주요 코드 스니펫

**🔹 목적: 렌더러 캐싱 타이밍**

```csharp
// CharacterSpawner.cs — SpawnVisual() 내부
GameObject visual = Instantiate(prefab, characterModelRoot);

var anim = visual.GetComponentInChildren<Animator>();
if (anim != null) OnCharacterSpawned?.Invoke(anim);

GetComponent<PlayerBushState>()?.CacheRenderers(characterModelRoot);
```

📌 **사용 이유:** visual이 Instantiate된 직후 호출해야 characterModelRoot 하위의 모든 Renderer가 존재하는 상태에서 캐싱됨. OnStartClient 이후라 SyncVar 초기값도 이미 적용된 상태.

📌 **주의할 점:** CacheRenderers 내부에서 `UpdateVisibility()`를 즉시 호출해 inBush=true 상태로 접속한 플레이어도 올바르게 숨김 처리됨.

## 🧠 오늘 배운 점

- Mirror SyncVar는 선언 순서대로 역직렬화되고 hook이 즉시 실행됨 → 여러 SyncVar가 함께 바뀔 때 의존 관계가 있으면 마지막 값에도 hook을 붙여야 함
- 다른 NetworkBehaviour의 SyncVar 변화에 반응하려면 C# event를 직접 연결해야 함 — SyncVar hook은 자기 오브젝트 전용
- 팀 상태처럼 여러 상태를 동시에 동기화할 때 비트마스크를 쓰면 SyncVar 1개로 해결 가능
- 데미지 팝업 같은 순수 시각 피드백은 NetworkServer.Spawn 없이 ClientRpc + 로컬 Instantiate 조합이 가볍고 적합함
