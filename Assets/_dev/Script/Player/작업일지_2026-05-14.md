## 1️⃣ 팀원 근접공격 이팩트·애니메이션 방지

### ✅ 결과
같은 팀원을 근접 공격해도 피격 이팩트와 Hit 애니메이션이 재생되지 않음

### 📌 수행 이유
`TakeDamage`에 팀 체크가 있어 데미지는 막혔지만, `RpcPlayHit` 호출이 팀 체크 이후에 있어도 `GetComponent<BattleNetworkPlayer>()`가 null 반환 시 체크를 통과해 버리는 엣지케이스 존재

### 📝 작업 내용
- `HitBox.cs` : `_ownerBnp`를 `Awake()`에서 캐싱 (매 프레임 GetComponent 제거)
- `CharacterWeapon.cs` : `_myBnp`를 `Awake()`에서 캐싱
- `PerformMelee` / `DashDamageAfterDelay` : `HashSet<GameObject>` 추가로 동일 루트의 콜라이더 중복 처리 방지

### ⚠️ 트러블슈팅

- **문제 :** 팀 체크 코드가 있는데도 팀원에게 피격 이팩트 재생
    - **원인 :** `GetComponent<BattleNetworkPlayer>()`를 매번 호출해 타이밍에 따라 null 반환 가능성, 또한 같은 플레이어의 콜라이더가 여러 개일 경우 중복 처리
    - **해결 방법 :** Awake에서 1회 캐싱 + HashSet으로 루트 오브젝트 기준 중복 제거

    **🧠 내가 이해한 원리 :**
    Mirror NetworkBehaviour에서 `GetComponent`는 언제든 유효하지만, 초기화 타이밍에 따라 SyncVar가 아직 세팅되지 않은 시점에 호출될 수 있음. Awake 캐싱으로 레퍼런스 자체는 확보하되 teamId는 이후 SetInfo에서 채워지므로 안전.

### 💻 주요 코드 스니펫

**🔹 목적: 중복 루트 방지 + 캐싱된 BNP로 팀 체크**

```csharp
// CharacterWeapon.cs — PerformMelee
var hitRoots = new HashSet<GameObject>();
foreach (var hit in hits)
{
    var root = hit.transform.root.gameObject;
    if (root == gameObject) continue;
    if (!hitRoots.Add(root)) continue; // 같은 루트 중복 스킵

    var targetBnp = root.GetComponent<BattleNetworkPlayer>();
    if (_myBnp != null && targetBnp != null && _myBnp.teamId == targetBnp.teamId) continue;
    ...
}
```

📌 **사용 이유 :** 캐릭터에 콜라이더가 여러 개 붙어있는 경우 동일 오브젝트를 두 번 처리하는 것을 방지

📌 **주의할 점 :** `hit.transform.root`가 항상 네트워크 오브젝트 루트임을 전제로 함. 캐릭터 계층구조 최상위에 NetworkBehaviour가 있어야 함

## 2️⃣ 사망 처리 완성

### ✅ 결과
- 사망 시 Rigidbody가 즉시 Kinematic으로 전환돼 낙하 없음
- HP바 캔버스 비활성화
- 로컬 플레이어 사망 시 살아있는 팀원으로 카메라 자동 전환

### 📌 수행 이유
기존 코드는 콜라이더 비활성화만 있었고, Rigidbody는 여전히 중력을 받아 캐릭터가 계속 내려가는 문제 존재. HP바도 사망 후 계속 표시됨.

### 📝 작업 내용
- `PlayerStats.cs` TakeDamage(Server): 사망 시 `rb.isKinematic = true` + velocity 초기화
- `PlayerStats.cs` RpcOnDeath(ClientRpc): 클라이언트도 동일하게 물리 정지, HP바 숨김
- `PlayerHPBar.cs` : `Hide()` 메서드 추가
- `PlayerStats.cs` : `FindAliveTeammate()` → `PlayerCameraFollow.target` 교체

### ⚠️ 트러블슈팅

- **문제 :** 사망 후 캐릭터가 계속 아래로 내려감
    - **원인 :** 콜라이더만 비활성화했고 Rigidbody는 여전히 중력 영향을 받음
    - **해결 방법 :** `rb.isKinematic = true` + `rb.linearVelocity = Vector3.zero`를 서버/클라이언트 모두에서 설정

    **🧠 내가 이해한 원리 :**
    Unity Rigidbody는 isKinematic = true 상태에서 물리 시뮬레이션(중력, 충돌)을 받지 않음. MovePosition/MoveRotation은 작동하지만 AddForce/velocity는 무시됨.

### 💻 주요 코드 스니펫

**🔹 목적: 사망 시 카메라를 살아있는 팀원으로 전환**

```csharp
// PlayerStats.cs
private Transform FindAliveTeammate()
{
    int myTeamId = GetComponent<BattleNetworkPlayer>()?.teamId ?? -1;
    if (myTeamId < 0) return null;

    foreach (var ps in FindObjectsByType<PlayerStats>(FindObjectsSortMode.None))
    {
        if (ps == this || ps.IsDead) continue;
        if (ps.GetComponent<BattleNetworkPlayer>()?.teamId == myTeamId)
            return ps.transform;
    }
    return null;
}
```

📌 **사용 이유 :** 2v2에서 한 명이 죽어도 팀원을 통해 전투 상황을 계속 관찰 가능

📌 **주의할 점 :** `FindObjectsByType`는 비용이 있으나 사망 시 1회 호출이므로 허용 범위

## 3️⃣ HP바 위치 및 구조 개선

### ✅ 결과
HP바가 모든 진영·거리에 관계없이 캐릭터 머리 위 고정 위치에 표시

### 📌 수행 이유
기존 `worldOffset.z = -1.5f` 고정값이 남쪽 카메라에서 적 팀(북쪽)에는 맞지만 아군(남쪽, 카메라 근접)에는 머리에 겹치는 문제

### 📝 작업 내용
- `hpCanvasTransform (Transform)` → `hpCanvas (GameObject)` 로 교체 (Inspector에서 직접 SetActive 가능)
- XZ 오프셋 제거, 순수 `Vector3.up * barHeight` 월드 Y 오프셋으로 단순화
- 회전은 `Quaternion.LookRotation(camTransform.forward)` 유지 (빌보드)

### ⚠️ 트러블슈팅

- **문제 :** 카메라 로컬 UP/RIGHT로 오프셋 계산 시 카메라가 움직일 때 HP바가 같이 흔들림
    - **원인 :** 카메라 로컬 방향은 카메라 회전에 종속되므로 월드 스페이스 캔버스에 부적합
    - **해결 방법 :** `Vector3.up * barHeight`만 사용. 빌보드 회전은 유지, 위치는 월드 Y축 고정

    **🧠 내가 이해한 원리 :**
    World Space Canvas는 위치를 월드 좌표로 직접 지정해야 안정적. 카메라 종속 오프셋은 Screen Space Overlay/Camera 방식에 적합함.

## 4️⃣ 북쪽 팀 스킬 조이스틱 방향 반전

### ✅ 결과
팀 1(북쪽 스폰) 플레이어의 스킬 발사 방향이 조이스틱 방향과 일치

### 📌 수행 이유
`PlayerMovement`에서 이동 방향은 `_inputSign`으로 반전했지만, `PlayerCombat`의 `ToAimDir3D`는 그대로 raw joystick 값을 사용해 스킬 방향이 반대였음

### 📝 작업 내용
- `PlayerCombat.cs` : `_aimSign` / `_aimSignInitialized` 추가, `GetAimSign()` 메서드
- `ToAimDir3D` static → 인스턴스 메서드로 변경, X·Z에 `_aimSign` 곱함
- `HandleMobileSkillDrag` 드래그 방향에도 동일 반전 적용

### 💻 주요 코드 스니펫

**🔹 목적: PlayerMovement와 동일한 팀 기반 부호 보정**

```csharp
private Vector3 ToAimDir3D(Vector2 dir2D)
{
    float s = GetAimSign();
    return new Vector3(dir2D.x * s, 0f, dir2D.y * s).normalized;
}

private float GetAimSign()
{
    if (!_aimSignInitialized && BattleNetworkPlayer.Local != null)
    {
        _aimSign = BattleNetworkPlayer.Local.teamId == 1 ? -1f : 1f;
        _aimSignInitialized = true;
    }
    return _aimSign;
}
```

📌 **주의할 점 :** `BattleNetworkPlayer.Local`이 확정되는 첫 프레임 이후에만 초기화. 그 전에는 1f(기본값) 유지

## 6️⃣ 전투 후 가챠 씬 복귀 버그

### ✅ 결과
전투 후 로비로 돌아와도 가챠 버튼 정상 작동

### 📌 수행 이유
`GachaSceneLoader`가 로비 진입 시 GachaScene을 Additive로 프리로드하는데, 배틀 씬 전환(Single 모드)이 이를 언로드해버림. 그러나 `_isPreloaded = true` 상태가 남아있어 복귀 후 무효화된 `AsyncOperation`을 사용 → `SetActiveScene` 실패

### 📝 작업 내용
- `SceneManager.sceneUnloaded` 구독: GachaScene 언로드 감지 시 `_isPreloaded = false` / `_preloadOp = null` 초기화
- `SceneManager.sceneLoaded` 구독: 로비 복귀 감지 시 자동으로 `PreloadRoutine` 재시작
- `Activate()` : `_preloadOp != null` 조건 추가해 stale 상태 방지
- `WaitAndActivate()` : preload가 없으면 직접 `PreloadRoutine` 시작 후 대기
- `ShopController.cs` : `GachaContext.OnGachaResult.Invoke()` → `?.Invoke()` (구독자 없을 때 NullReference 방지)

### ⚠️ 트러블슈팅

- **문제 :** `ArgumentException: SceneManager.SetActiveScene failed; invalid scene`
    - **원인 :** `LoadSceneMode.Single`로 배틀 씬 로드 시 모든 Additive 씬(GachaScene 포함)이 언로드되는데, `_isPreloaded` 플래그는 초기화되지 않아 stale `AsyncOperation` 참조 유지
    - **해결 방법 :** `sceneUnloaded` 이벤트로 GachaScene 언로드를 감지해 상태 초기화, `sceneLoaded`로 로비 복귀 시 자동 재프리로드

    **🧠 내가 이해한 원리 :**
    Unity `LoadSceneMode.Single`은 현재 로드된 모든 씬을 언로드 후 새 씬을 로드함. `allowSceneActivation = false`로 대기 중인 Additive 씬도 이 과정에서 사라짐. `DontDestroyOnLoad` 오브젝트는 살아있어도 씬 참조(`AsyncOperation`)는 무효화됨.

### 💻 주요 코드 스니펫

**🔹 목적: 외부 언로드 감지 및 자동 복구**

```csharp
private void OnAnySceneUnloaded(Scene scene)
{
    if (scene.name == GACHA_SCENE)
    {
        _isPreloaded = false;
        _preloadOp   = null;
    }
}

private void OnAnySceneLoaded(Scene scene, LoadSceneMode mode)
{
    if (scene.name == "MainLobbyScene" && _preloadOp == null && !_isPreloaded)
        StartCoroutine(PreloadRoutine());
}
```

📌 **사용 이유 :** GachaSceneLoader가 DontDestroyOnLoad이므로 씬 이벤트를 구독해 생명주기 관리

📌 **주의할 점 :** `MainLobbyScene` 이름이 빌드 세팅의 씬 이름과 정확히 일치해야 함

---

## 🧠 오늘 배운 점

- `LoadSceneMode.Single`은 Additive로 로드된 씬도 전부 언로드함. DontDestroyOnLoad 오브젝트가 씬 참조를 들고 있으면 stale 상태가 될 수 있어 씬 이벤트로 동기화해야 함
- World Space Canvas HP바는 위치를 카메라 로컬 방향으로 계산하면 카메라 이동 시 흔들림. 월드 Y축 고정 + LookRotation이 가장 안정적인 빌보드 구현
- Mirror에서 팀 체크는 클라이언트·서버 양측 모두에서 해야 함. 서버 판정(`[Server]`)만 믿으면 클라이언트 RPC에서 빠져나가는 케이스가 생길 수 있음
