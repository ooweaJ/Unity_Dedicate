## 1️⃣ 장비 강화 UI 시스템

### ✅ 결과

강화 클릭 → 서버 프리뷰 수신(현재 강화 수치 / 성공률 / 골드 비용) → 강화 버튼 활성화 → 클릭 시 색상 + 회전 애니메이션 → 결과 수신 후 파란색(성공) 또는 빨간색(실패)으로 전환

### 📌 수행 이유

강화 결과를 단순 텍스트로 즉시 표시하면 유저가 인지하기 어려움. 최소 2초 애니메이션으로 긴장감 부여, 색상으로 결과를 직관적으로 전달

### 📝 작업 내용

- `EnhancePanel.cs` 신규 작성
  - `Open(equipInstanceId, itemName, icon)` : `gameObject.SetActive(true)`, 아이콘·로딩 상태 초기화
  - `SetPreviewData(currentEnhance, successRate, goldCost)` : UI 채우기, 강화 버튼 활성화
  - `SetMaxEnhance()` : 최대 강화 상태 표시, 버튼 비활성화
  - `OnEnhanceClicked()` : `AnimateColors()` 코루틴 시작, `OnEnhanceRequested` 이벤트 발행
  - `ShowResult(success, enhance)` : `minAnimDuration(2f)` 이후 색상 고정
  - `AnimateColors()` : `UnityEngine.Random.ColorHSV()` + Z축 회전 반복
- `BackendManager.cs` : `GetEnhancePreview(userId, equipInstanceId)` GET 엔드포인트 추가
- `equipmentController.js` / `equipment.js` : `GET /:userId/enhance/:equipInstanceId/preview` 라우트 추가
- `InventoryController.cs`
  - `HandleEnhancePreview` : 프리뷰 응답 파싱 → `ShowEnhancePreview` / `ShowEnhanceMaxEnhance`
  - `HandleEnhanceEquipment` : 강화 응답 파싱 → `ShowEnhanceResult` / `ShowEnhanceError`

### ⚠️ 트러블슈팅

- **문제 :** `Random.ColorHSV()`에서 `'Random' is ambiguous` 컴파일 에러
  - **원인 :** `using System`과 `using UnityEngine` 둘 다 `Random` 클래스를 가짐
  - **해결 방법 :** `UnityEngine.Random.ColorHSV()`로 네임스페이스 명시
  - **🧠 내가 이해한 원리 :** C# 네임스페이스 충돌은 암시적 using만으로는 해결 불가. 동일 이름 클래스가 둘 이상 임포트되면 전체 경로 명시 필요

- **문제 :** 강화 팝업(EnhancePanel) 이 전혀 나타나지 않음
  - **원인 :** EnhancePanel에 별도 `panel` 필드를 두고 `panel.SetActive(true)`를 했는데, 인스펙터에서 해당 필드가 미할당 상태 → `?.` 연산자가 조용히 스킵
  - **해결 방법 :** `panel` 필드 제거, `gameObject.SetActive(true/false)` 직접 사용
  - **🧠 내가 이해한 원리 :** MonoBehaviour 컴포넌트는 자기 자신의 `gameObject`를 바로 켜고 끄면 간단. 불필요한 간접 참조는 미할당 버그를 유발

### 💻 주요 코드 스니펫

**🔹 목적: 최소 애니메이션 시간 보장 후 결과 색상 표시**

```csharp
private IEnumerator ShowResultAfterMinDuration(bool success, int enhance)
{
    float elapsed = Time.time - _animStartTime;
    if (elapsed < minAnimDuration)
        yield return new WaitForSeconds(minAnimDuration - elapsed);

    StopAnim();
    if (enhanceAnimImage != null)
    {
        enhanceAnimImage.color                   = success ? ResultSuccess : ResultFail;
        enhanceAnimImage.transform.localRotation = Quaternion.identity;
    }
}
```

📌 **사용 이유 :** 서버 응답이 빠르게 오더라도 유저가 결과를 인지할 수 있도록 최소 2초 보장

📌 **주의할 점 :** `_animStartTime`은 `OnEnhanceClicked()` 시점에 기록해야 경과 시간 계산이 정확

## 3️⃣ 초월 시스템 전면 개편

### ✅ 결과

초월 탭 진입 시 TranscendPanel 항상 표시. + / - 버튼으로 투입 조각 수 선택 → 확률 실시간 표시 → 초월 버튼 클릭 시 서버 전송. 서버에서 확률 기반 성공 여부 결정 (조각은 실패해도 소모)

### 📌 수행 이유

기존 초월은 조각 수를 정확히 맞춰야 100% 성공. 이를 확률 기반으로 바꿔 적은 조각으로 도전하는 재미를 추가. 또한 초월 UI가 따로 없어 사용하기 불편했음

### 📝 작업 내용

- `TranscendPanel.cs` 신규 작성
  - `Init(characterId, currentStage, currentShards)` : 단계 텍스트, 보유 조각, 초기 투입 수(1) 설정
  - `SetShardsToUse(value)` : 1 ~ min(보유조각, shardsRequired) 클램프, 확률 = shardsToUse / shardsRequired × 100
  - `ShowResult / ShowError` : 버튼 비활성화 (메시지는 InventoryUIManager가 MessagePanel로 출력)
- `user_characterService.js` : `shardsToUse` 파라미터 수신, `Math.random() < successRate` 판정, 실패해도 조각 차감
- `userController.js` : `req.body.shardsToUse` 파싱
- `BackendManager.cs` : `TranscendCharacter(userId, characterId, shardsToUse)` 바디에 `shardsToUse` 추가
- `InventoryUIManager.cs` : `OnSelectCharacter`에서 `transcendPanel?.Init(...)` 호출

### ⚠️ 트러블슈팅

- **문제 :** TranscendPanel에 데이터가 전혀 표시되지 않음. 초월 인벤토리 슬롯도 그려지지 않음
  - **원인 :** `ItemType.Material`(index 2)을 제거하면서 `Transcendence`의 인덱스가 3→2로 밀림. 인스펙터에 직렬화된 `InventoryUI.targetType` 값이 여전히 3(유효하지 않은 인덱스)을 가리킴
  - **해결 방법 :** 인스펙터에서 영향받은 `InventoryUI` 컴포넌트의 `targetType`을 `Transcendence`로 재선택
  - **🧠 내가 이해한 원리 :** Unity는 enum을 이름이 아닌 정수 인덱스로 직렬화함. enum 중간 값을 삭제하면 인덱스가 밀려 기존 씬/프리팹 데이터가 깨짐. 삭제 대신 Obsolete 처리하거나 맨 끝으로 이동하는 것이 안전

### 💻 주요 코드 스니펫

**🔹 목적: 확률 실시간 계산 및 버튼 상태 갱신**

```csharp
private void SetShardsToUse(int value)
{
    _shardsToUse = Mathf.Clamp(value, 1, _maxShardsToUse);
    float probability = (float)_shardsToUse / _shardsRequired * 100f;

    if (shardsRatioText != null) shardsRatioText.text  = $"( {_shardsToUse} / {_shardsRequired} )";
    if (probabilityText != null) probabilityText.text  = $"확률 : {(int)probability}%";
    if (btnMinus        != null) btnMinus.interactable = _shardsToUse > 1;
    if (btnPlus         != null) btnPlus.interactable  = _shardsToUse < _maxShardsToUse;
}
```

📌 **사용 이유 :** 확률은 클라이언트에서 표시용으로만 계산, 실제 판정은 서버가 동일한 공식으로 처리

📌 **주의할 점 :** `_shardsRequired = currentStage + 1` (다음 단계 번호 = 필요 조각 수)

## 5️⃣ 공용 MessagePanel 구현

### ✅ 결과

강화/초월 결과·에러 메시지를 단일 `MessagePanel` 싱글톤이 처리. `InventoryUIManager`가 참조를 보유하고 Show* 메서드마다 호출

### 📌 수행 이유

EnhancePanel, TranscendPanel 각각에 상태 텍스트를 두면 중복이 발생하고 UI 배치도 복잡해짐. 공용 팝업 하나로 통일

### 📝 작업 내용

- `MessagePanel.cs` 신규 작성
  - `UIMessageType` enum : `Info`, `Success`, `Fail`, `Error` (기존 `MessageType`은 `UnityEditor.MessageType`과 충돌)
  - `Awake()` : `Instance = this`, 확인 버튼 리스너 등록, `SetActive(false)`
  - `Show(message, type)` : 텍스트·색상 설정 후 `SetActive(true)`
  - `Hide()` : `SetActive(false)` (코루틴 없음)
- `InventoryUIManager.cs` : `messagePanel` 필드 추가, 모든 Show* 메서드에서 `messagePanel?.Show(...)` 호출

### ⚠️ 트러블슈팅

- **문제 :** `MessageType.Warning`에서 `CS0117` 컴파일 에러 (외부 에셋 Cartoon FX)
  - **원인 :** 우리가 만든 `MessageType` enum이 `UnityEditor.MessageType`과 이름 충돌
  - **해결 방법 :** `UIMessageType`으로 이름 변경
  - **🧠 내가 이해한 원리 :** Unity 에디터 네임스페이스 타입과 동일한 이름의 타입을 전역으로 선언하면 외부 에셋 코드에서도 모호성 에러 발생. 프로젝트 전용 Prefix를 붙이는 습관 필요

- **문제 :** `Coroutine couldn't be started because the GameObject 'MessagePanel' is inactive!`
  - **원인 :** MessagePanel이 `SetActive(false)` 상태일 때 Show()에서 코루틴을 시작하려 함
  - **해결 방법 :** 코루틴 + 애니메이션 완전 제거. `SetActive(true)` → 텍스트/색상 설정 순서로 변경 (SetActive 전에 내용을 채우면 Awake가 재실행되지 않으므로 안전)
  - **🧠 내가 이해한 원리 :** `StartCoroutine`은 해당 GameObject가 활성 상태일 때만 실행 가능. 비활성 오브젝트를 켜기 전에 코루틴을 걸면 항상 에러. 단순 SetActive 패턴이 가장 안전

### 💻 주요 코드 스니펫

**🔹 목적: 코루틴 없이 메시지 표시**

```csharp
public void Show(string message, UIMessageType type = UIMessageType.Info)
{
    if (messageText != null)
    {
        messageText.text  = message;
        messageText.color = type switch
        {
            UIMessageType.Success => colorSuccess,
            UIMessageType.Fail    => colorFail,
            UIMessageType.Error   => colorError,
            _                     => colorInfo
        };
    }
    gameObject.SetActive(true);
}
```

📌 **사용 이유 :** SetActive 전에 내용을 채워야 오브젝트가 켜질 때 올바른 상태로 표시됨

📌 **주의할 점 :** MessagePanel은 씬에서 항상 활성 상태로 시작해야 `Awake()`가 실행되어 싱글톤 등록 및 버튼 리스너가 정상 동작

## 🧠 오늘 배운 점

- Unity는 enum을 정수 인덱스로 직렬화한다. enum 중간 값 삭제는 씬 데이터를 깨뜨린다
- `StartCoroutine`은 GameObject가 활성 상태일 때만 호출 가능. 비활성 객체에는 코루틴 대신 단순 상태 전환 사용
- 동일 이름의 클래스가 여러 네임스페이스에 존재하면 전체 경로 명시 필요 (`UnityEngine.Random`, `UIMessageType` 등)
- MonoBehaviour 컴포넌트는 별도 panel 필드 없이 `gameObject.SetActive()`로 자기 자신을 직접 제어하는 것이 단순하고 안전
