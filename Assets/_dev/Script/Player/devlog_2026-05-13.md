## 1️⃣ 상태이상 바 (StatusEffectBar)

### ✅ 결과

HP바 영역에 `Image.fillAmount` 기반 바를 추가해 상태이상 지속시간을 시각화

### 📌 수행 이유

슬라이더는 원형 핸들이 붙어서 시각적으로 어울리지 않음 → 순수 Image Fill 방식으로 대체

### 📝 작업 내용

- `StatusEffectBar.cs` 신규 생성 — `PlayerHPBar`와 같은 오브젝트에 부착
- `Image.Type.Filled` + `FillMethod.Horizontal` + `OriginHorizontal.Left` 설정
- 상태이상 타입별 색상: 기절=노랑, 슬로우=파랑, 중독=보라
- `Deplete()` 코루틴으로 `fillAmount` 1→0 감소 (지속시간 비례 속도)
- `PlayerHPBar`에 `ShowStatusText()` / `RestoreNickname()` 추가
- `StatusEffectHandler`에 `RpcShowStatusEffect` / `RpcHideStatusEffect` 추가 — 서버 코루틴에서 RPC 호출

### ⚠️ 트러블슈팅

- **문제:** 없음 (설계 단계에서 Slider 방식 기각)
- **원인:** Slider의 기본 핸들(원형 이미지)이 UI 톤과 맞지 않음
- **해결 방법:** `Image.fillAmount` 직접 제어

**🧠 내가 이해한 원리:**
`Image.Type.Filled`는 UV 클리핑으로 이미지를 비율만큼 잘라냄. Slider처럼 별도 컴포넌트 없이 fillAmount 0~1만으로 동일한 시각 효과를 낼 수 있음

### 💻 주요 코드 스니펫

**🔹 목적: 지속시간 비례로 바 감소**

```csharp
private IEnumerator Deplete(float duration)
{
    fillImage.fillAmount = 1f;
    float elapsed = 0f;
    while (elapsed < duration)
    {
        elapsed             += Time.deltaTime;
        fillImage.fillAmount = 1f - Mathf.Clamp01(elapsed / duration);
        yield return null;
    }
    fillImage.gameObject.SetActive(false);
    _hpBar?.RestoreNickname();
}
```

📌 **사용 이유:** WaitForSeconds 대신 매 프레임 계산으로 정확한 비율 반영
📌 **주의할 점:** `fillImage.gameObject`를 비활성화해야 함 — 부모(PlayerHPBar)가 아닌 fillImage 자체

## 2️⃣ 쿨타임 UI — 아이콘 디밍 + 준비완료 펄스

### ✅ 결과

쿨타임 중 스킬 아이콘이 `dimAlpha(0.4)`로 어두워지고, 쿨타임 종료 시 1.25배 스케일 펄스 후 복귀

### 📌 수행 이유

Radial360 Fill만으로는 쿨타임 여부를 직관적으로 알기 어려움. 아이콘 밝기 변화 + 준비 알림 피드백 필요

### 📝 작업 내용

- `VirtualJoystickButton`에 `iconImage`, `dimAlpha`, `readyPulseDuration` 필드 추가
- `_wasOnCooldown` 플래그로 쿨타임→준비 전환 감지
- `SetCooldownRatio()`에서 alpha 제어 + 전환 시 `TriggerReadyPulse()` 호출
- `ReadyPulse()` 코루틴: `localScale`을 1→1.25→1 으로 보간 (`readyPulseDuration` 안에)

### ⚠️ 트러블슈팅

- **문제:** 없음

### 💻 주요 코드 스니펫

**🔹 목적: 쿨타임 상태에 따라 아이콘 알파 제어 및 펄스 트리거**

```csharp
public void SetCooldownRatio(float ratio)
{
    if (cooldownFill != null)
        cooldownFill.fillAmount = ratio;

    bool onCooldown = ratio > 0f;

    if (iconImage != null)
    {
        Color c = iconImage.color;
        c.a = onCooldown ? dimAlpha : 1f;
        iconImage.color = c;
    }

    if (_wasOnCooldown && !onCooldown)
        TriggerReadyPulse();

    _wasOnCooldown = onCooldown;
}
```

📌 **사용 이유:** `_wasOnCooldown` 플래그로 매 프레임 호출되는 SetCooldownRatio에서 전환 시점(edge)만 정확히 감지
📌 **주의할 점:** `iconImage.transform.localScale`을 펄스가 끝날 때 반드시 `Vector3.one`으로 복원해야 함

## 3️⃣ 전투 버튼 UI 구조 설계

### ✅ 결과

원형 버튼 프리팹 구조 확정 — 이동 조이스틱과 스킬 버튼 동일 계층 사용

### 📌 수행 이유

모바일 환경에서 스킬도 드래그 방향으로 발동하는 미니 조이스틱 방식 채택

### 📝 작업 내용

프리팹 계층 확정:
```
JoystickButton  (VirtualJoystickButton + Image[원형] + Mask)
├── Background   (Image — 어두운 반투명 원)
├── IconImage    (Image — 스킬 아이콘)
├── CooldownFill (Image — Radial360, 반투명 검정)
└── Knob         (Image — 작은 원, 드래그 추적)
```

- `Button` 컴포넌트 미사용 — `IPointerDownHandler / IDragHandler / IPointerUpHandler` 직접 구현
- 이동 조이스틱은 동일 구조에서 Icon·Cooldown 생략
- 원형 클리핑: 원형 스프라이트 + `Mask` 컴포넌트 (쉐이더 불필요)

## 🧠 오늘 배운 점

- `Image.Type.Filled`는 Slider 없이도 진행 바 역할을 완전히 대체할 수 있음
- Unity `Button` 컴포넌트는 탭(PointerDown+Up 동일 위치)만 처리 — 드래그 방향 발동에는 인터페이스 직접 구현이 필수
- `_wasOnCooldown` 플래그 패턴: 매 프레임 호출되는 메서드에서 상태 전환 시점(edge)만 뽑아내는 범용 기법
