## 1️⃣ 컴포짓 스킬 시스템 (SkillData + SkillAction)

### ✅ 결과
스킬 하나에 `List<SkillAction>`을 순서대로 실행하는 시퀀스 구조. 대시 후 근접 공격, 더블 대시 등 자유롭게 조합 가능.

### 📌 수행 이유
"대시 후 도착 지점에서 주변 근접 공격"을 하나의 스킬로 만들어야 했음. 기존 단일 AttackData 구조로는 불가능.

### 📝 작업 내용
- `AttackData` → `SkillAction` 리네임, `cooldown` 제거, `delay`(딜레이) 추가
- `SkillData` 신규 생성 — `cooldown` + `SkillInputType` + `List<SkillAction>`
- `CharacterDataSO`의 공격 3개 필드 → `SkillData[] skills` 배열로 교체
- `CharacterWeapon.ExecuteSkill()`을 코루틴으로 변경 — 액션마다 `yield WaitForSeconds(action.delay)`

### 💻 주요 코드 스니펫

**🔹 목적: 스킬 시퀀스를 코루틴으로 순서 실행**

```csharp
[Server]
private IEnumerator ExecuteSkill(Vector3 origin, Vector3 aimDir, Vector3 targetPos, int skillIndex)
{
    var skill = GetSkill(skillIndex);
    if (skill?.actions == null) yield break;

    foreach (var action in skill.actions)
    {
        if (action.delay > 0f) yield return new WaitForSeconds(action.delay);
        // Melee / Projectile / Dash 분기 실행
    }
}
```

📌 **사용 이유 :** 각 액션 사이에 딜레이를 두어 대시 후 착지 타이밍에 근접 판정을 넣을 수 있음.

📌 **주의할 점 :** `[Server]` 코루틴이므로 `StartCoroutine`은 서버에서만 호출. 클라이언트는 `RpcPlayAnimation`으로 시각 처리.

## 2️⃣ 투사체 데이터 SO 상속 구조 + ProjectileManager

### ✅ 결과
`ProjectileDataSO`(기본) → `ExplosiveProjectileDataSO`, `BouncingProjectileDataSO` 상속 체계. 인스펙터에서 타입별 필드만 노출됨.

### 📌 수행 이유
폭발형 투사체의 폭발 반경·Falloff 같은 전용 변수가 기본 투사체 인스펙터에 노출되는 문제 해결 필요. 투사체 행동 프리팹과 비주얼 프리팹을 분리해야 Mirror 네트워크 동기화 가능.

### 📝 작업 내용
- SO 상속으로 타입별 전용 필드 분리
- `ProjectileType` enum → `ProjectileManager`가 행동 프리팹 반환
- 비주얼 프리팹은 `int visualIndex`로 SyncVar 동기화 후 클라이언트에서 자식 오브젝트로 Instantiate
- `Dictionary<GameObject, int>` 빌드로 O(1) 인덱스 조회

### ⚠️ 트러블슈팅

- **문제 :** Mirror SyncVar에 SO의 `GameObject visualPrefab`을 직접 넣을 수 없음
    - **원인 :** SyncVar는 네트워크로 등록된 NetworkObject만 동기화 가능. 일반 프리팹 레퍼런스는 지원 안 함.
    - **해결 방법 :** `ProjectileManager.visuals[]` 배열에 모든 비주얼 프리팹 등록 → 서버가 `int visualIndex`를 SyncVar로 보냄 → 클라이언트가 배열에서 꺼내 자식으로 붙임.

    **🧠 내가 이해한 원리 :**
    SO의 `visualPrefab` 필드는 서버가 인덱스를 찾기 위한 키(key)로 사용됨. 인스펙터에서 드래그앤드롭으로 직관적으로 연결하면서, 내부적으로는 인덱스로 변환해 네트워크를 타는 구조.

### 💻 주요 코드 스니펫

**🔹 목적: Falloff 감쇠 데미지 계산**

```csharp
float range   = Mathf.Max(0.01f, explosionRadius - explosionInnerRadius);
float falloff = 1f - Mathf.Clamp01((dist - explosionInnerRadius) / range);
float finalDmg = damage * explosionMultiplier * falloff;
```

📌 **사용 이유 :** 폭발 중심은 풀 데미지, 외곽으로 갈수록 선형 감소. `innerRadius` 이내는 항상 100%.

📌 **주의할 점 :** `explosionInnerRadius >= explosionRadius`이면 range가 0에 가까워져 나눗셈 오류 발생 → `Mathf.Max(0.01f, ...)` 가드 필수.

## 3️⃣ 상태이상 시스템 (StatusEffectHandler)

### ✅ 결과
`StatusEffectHandler` 단일 컴포넌트가 모든 상태이상을 서버 권위로 관리. 스킬 데이터의 `onHitEffect`만 설정하면 자동 적용.

### 📌 수행 이유
넉백이 전혀 동작하지 않는 버그 발견 → 근본 원인 분석 후 전체 상태이상 시스템 재설계.

### 📝 작업 내용
- `StatusEffectType`에 `DotDamage` 추가, `interval` 필드 추가
- `StatusEffectHandler` 신규 컴포넌트 생성
  - `[SyncVar] bool _isStunned` → 훅으로 `PlayerMovement.SetStunned()` 호출
  - `[SyncVar] float _slowMultiplier` → 훅으로 `PlayerMovement.SetSlowMultiplier()` 호출
  - 서버 코루틴으로 스턴·슬로우 타이머 관리
  - `DotCoroutine` — 틱마다 `TakeDamage` 호출
  - `OnKnockbackWallHit()` — 넉백 중 벽 충돌 시 자동 기절
- `PlayerMovement` 수정 — 스턴·슬로우 상태 반영, 벽 충돌 감지 후 `CmdNotifyWallHit`
- `CharacterWeapon.CanUse()` — 스턴 상태면 입력 차단

### ⚠️ 트러블슈팅

- **문제 :** 넉백이 전혀 동작하지 않음
    - **원인 1 :** 기존 코드가 서버에서 `Rigidbody.AddForce()`를 호출했는데, 클라이언트의 `PlayerMovement.Move()`가 매 `FixedUpdate`마다 `rb.linearVelocity`를 **직접 할당**해서 덮어씀.
    - **원인 2 :** `Move()`는 로컬 클라이언트에서 실행되고, `AddForce`는 서버 Rigidbody에만 적용 → 클라이언트 물리에는 영향 없음.
    - **해결 방법 :** `[ClientRpc] RpcApplyKnockback` — 클라이언트에서 직접 `linearVelocity` 설정 + `_isKnockedBack` 플래그로 `Move()` 개입 차단.

    **🧠 내가 이해한 원리 :**
    대시는 `DashCoroutine`이 매 `WaitForFixedUpdate`마다 velocity를 **재설정**해서 `Move()`가 덮어써도 바로 회복됨. 넉백은 1회만 설정하므로 다음 프레임 `Move()`가 덮어쓰면 사라짐. 따라서 `_isKnockedBack` 플래그로 `Move()`를 일시 차단해야 함.

### 💻 주요 코드 스니펫

**🔹 목적: 넉백 RPC — 클라이언트 Rigidbody에 직접 충격 후 Move() 차단**

```csharp
[ClientRpc]
public void RpcApplyKnockback(Vector3 dir, float force)
{
    if (!isLocalPlayer) return;
    Vector3 flat = new Vector3(dir.x, 0f, dir.z).normalized;
    rb.linearVelocity = new Vector3(flat.x * force, rb.linearVelocity.y, flat.z * force);
    _isKnockedBack    = true;
    _knockbackEndTime = Time.time + KnockbackMoveLockDuration;
}
```

📌 **사용 이유 :** 서버가 아닌 로컬 클라이언트에서 직접 velocity를 설정해야 `Move()`와 충돌 없이 작동함.

📌 **주의할 점 :** `isLocalPlayer` 체크 필수. 안 하면 모든 클라이언트의 해당 플레이어 오브젝트에 velocity가 적용됨.

**🔹 목적: 넉백 중 벽 충돌 → 서버에 기절 요청**

```csharp
private void OnCollisionEnter(Collision col)
{
    bool touchedWall = false;
    foreach (ContactPoint c in col.contacts)
    {
        if (Vector3.Angle(c.normal, Vector3.up) > MaxGroundAngle)
            touchedWall = true;
    }
    if (touchedWall && _isKnockedBack && isLocalPlayer)
    {
        _isKnockedBack = false;
        CmdNotifyWallHit(); // 서버 → StatusEffectHandler.OnKnockbackWallHit()
    }
}
```

📌 **사용 이유 :** 벽 충돌은 클라이언트가 먼저 감지. `[Command]`로 서버에 알려 스턴을 공식 적용.

## 4️⃣ 모바일 입력 시스템 (VirtualJoystickButton + MobileCombatUI)

### ✅ 결과
공격 버튼 3개가 각각 독립된 조이스틱. 누른 채로 드래그해서 방향·세기 결정, 떼면 발사. 쿨타임은 fillAmount로 시각화.

### 📌 수행 이유
크로스 플랫폼(PC·모바일) 지원. 브롤스타즈처럼 각 공격 버튼이 조준 조이스틱을 겸하는 방식(Method A) 채택.

### 📝 작업 내용
- `VirtualJoystickButton` — `IPointerDown/IDrag/IPointerUp` 구현. `OnFire: Action<Vector2, float>` 이벤트. CooldownFill로 쿨타임 표시.
- `MobileCombatUI` — `NetworkClient.localPlayer`로 자동 바인딩. 매 프레임 `GetCooldownRatio()` → `SetCooldownRatio()`.

### 💻 주요 코드 스니펫

**🔹 목적: 드래그 방향·세기를 계산해 OnFire 발동**

```csharp
public void OnPointerUp(PointerEventData e)
{
    if (!_isPressed) return;
    _isPressed = false;
    Vector2 delta     = e.position - _pointerStart;
    float   magnitude = Mathf.Clamp01(delta.magnitude / maxDragRadius);
    if (magnitude >= minMagnitude)
        OnFire?.Invoke(delta.normalized, magnitude);
    MoveKnob(Vector2.zero);
}
```

📌 **사용 이유 :** 손가락을 뗄 때 발동. magnitude가 minMagnitude 미만이면 오발 방지.

📌 **주의할 점 :** `TargetPoint` 스킬(수류탄 등)은 magnitude로 착탄 거리를 결정하므로, float 두 번째 파라미터를 반드시 `CharacterWeapon.ComputeTargetPos()`에 전달해야 함.

## 🧠 오늘 배운 점

- **Mirror SyncVar는 non-networked GameObject 불가** — SO의 prefab 레퍼런스는 직접 동기화할 수 없고, 인덱스 변환 후 카탈로그 배열로 우회해야 함.
- **rb.linearVelocity 직접 할당은 AddForce를 즉시 무효화** — 이동 컴포넌트가 velocity를 할당 방식으로 제어하면, 외부에서 가해진 충격이 다음 프레임에 사라짐.
- **대시 vs 넉백 메커니즘 차이** — 대시는 코루틴이 매 프레임 velocity를 재설정(덮여도 복구), 넉백은 1회성 → 플래그로 Move() 차단이 필수.
- **StatusEffectHandler 분리의 이점** — `PlayerStats`(체력), `PlayerMovement`(물리), `CharacterWeapon`(공격) 각각 상태이상의 "결과"만 받음. 상태이상 로직이 한 곳에 집중돼 추후 DoT 추가, 중첩 처리 등이 용이.
