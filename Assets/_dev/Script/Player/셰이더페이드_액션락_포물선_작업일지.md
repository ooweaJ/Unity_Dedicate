## 1️⃣ 액션 락 (_isActing)

### ✅ 결과

스킬 실행 코루틴 구간 동안 추가 스킬 입력이 서버/클라이언트 양쪽에서 차단됨

### 📌 수행 이유

Dash → Melee 같은 멀티 액션 스킬 실행 중 중간에 다른 스킬이 끼어들면 액션 순서가 깨지고 데미지가 중복 발생할 수 있음

### 📝 작업 내용

- `CharacterWeapon`에 `[SyncVar] private bool _isActing` 추가
- `CanUse()` — `_isActing` 체크 추가
- `CmdUseAttack()` — 서버에서도 `_isActing` 체크 (클라이언트 우회 방지)
- `ExecuteSkill()` — 시작 시 `_isActing = true`, 종료 시 `false`

### 💻 주요 코드 스니펫

**🔹 목적: 서버·클라이언트 이중 차단**

```csharp
// CharacterWeapon.cs
[SyncVar] private bool _isActing;

// CanUse() 내부
if (_isActing) return false;

// CmdUseAttack() 내부
if (_isActing) return;

// ExecuteSkill() 코루틴
_isActing = true;
foreach (var action in skill.actions) { ... }
_isActing = false;
```

📌 **사용 이유:** `SyncVar`이므로 서버에서 true로 설정하면 모든 클라이언트의 `CanUse`도 즉시 막힘. 클라이언트 입력 버퍼(`_bufAttackTime` 등)와도 연동되어 쿨다운 만료 후 버퍼 재시도도 차단됨.

📌 **주의할 점:** `ExecuteSkill` 코루틴이 예외로 중단되면 `_isActing`이 영구 잠김. 추후 타임아웃 안전장치 고려.

## 2️⃣ 포물선 투사체 (ExplosiveProjectile Arc)

### ✅ 결과

`OnTargetReached` 트리거 설정 시 착탄 지점을 향해 수류탄처럼 포물선 비행 후 착지 즉시 폭발

### 📌 수행 이유

직선 비행은 수류탄 느낌이 없고, 지형지물 뒤에 숨은 적에게 던질 수 없음. 포물선 궤도가 게임플레이상 더 자연스럽고 전략적임.

### 📝 작업 내용

- `ExplosiveProjectileDataSO`에 `arcHeight` 필드 추가
- `ExplosiveProjectile.SetTargetPosition()`에서 `_spawnPos`, `_targetDist`, `_arcHeight` 저장
- `FixedUpdate` — `OnTargetReached` 트리거면 `MoveArc()` 호출, 나머지는 기존 직선 이동
- `MoveArc()` — XZ는 선형 보간, Y는 포물선 공식 적용

### 💻 주요 코드 스니펫

**🔹 목적: 포물선 Y 계산**

```csharp
private void MoveArc()
{
    traveledDistance += speed * Time.fixedDeltaTime;
    float t = _targetDist > 0f ? Mathf.Clamp01(traveledDistance / _targetDist) : 1f;

    Vector3 flatPos = Vector3.Lerp(
        new Vector3(_spawnPos.x, 0, _spawnPos.z),
        new Vector3(_targetPos.x, 0, _targetPos.z), t);

    float arcY     = _arcHeight * 4f * t * (1f - t);   // t=0.5 에서 최대
    Vector3 nextPos = new Vector3(flatPos.x, _spawnPos.y + arcY, flatPos.z);

    Vector3 moveDir = nextPos - rb.position;
    if (moveDir != Vector3.zero) transform.rotation = Quaternion.LookRotation(moveDir);
    rb.MovePosition(nextPos);

    if (t >= 1f) { Explode(); DestroySelf(); }
}
```

📌 **사용 이유:** `4t(1-t)` 공식은 t=0·1에서 0, t=0.5에서 1 — 자연스러운 포물선. 서버 전용(`rb.MovePosition`)이므로 클라이언트는 NetworkTransform으로 동기화.

📌 **주의할 점:** `SetTargetPosition`은 반드시 `NetworkServer.Spawn` 이전에 호출해야 초기 SyncVar 값이 클라이언트에 전달됨.

## 3️⃣ 셰이더별 투명 처리 시스템

### ✅ 결과

`ShaderFadeProfile` SO 하나만 교체하면 URP Lit / Standard / UTS Toon 등 어떤 셰이더도 투명 처리 가능

### 📌 수행 이유

캐릭터마다 셰이더가 다름 (URP 캐릭터 vs Unity-chan UTS2 Toon). 하드코딩하면 캐릭터 추가마다 코드 수정 필요. SO 기반으로 외부 설정화.

### 📝 작업 내용

- `ShaderFadeProfile.cs` (SO) — `Auto`(URP/Standard 자동 감지) / `PropertyValue`(프로퍼티 직접 지정) 두 모드
- `CharacterVisualConfig.cs` — 비주얼 프리팹 루트에 붙이는 설정 컴포넌트, `fadeProfile` 연결
- `PlayerBushState.CreateFadeMaterial()` — profile에 따라 분기 처리
  - `PropertyValue`: `_SrcBlend`/`_DstBlend`/`_ZWrite`/`renderQueue` 강제 설정 + 지정 프로퍼티 값 적용
  - `Auto`: `_Surface`(URP) → `_Mode`(Standard) → Fallback 순서로 자동 감지

**Unity-chan UTS2 Toon 설정값:**

| 항목 | 값 |
|---|---|
| Type | PropertyValue |
| propertyName | `_Tweak_transparency` |
| fadeValue | `-0.4` |

### ⚠️ 트러블슈팅

- **문제:** 투명이 적용되지 않고 shader=Toon/Toon, renderQ=3000 인데 변화 없음
    - **원인 1:** `profile=null(Auto)` 로그 → `CharacterVisualConfig`가 없는 것처럼 동작
    - **원인 2 (진짜 원인):** `GetComponent<CharacterVisualConfig>()`를 `characterModelRoot`(빈 부모 오브젝트)에서 호출했는데, 실제 컴포넌트는 그 **자식**인 비주얼 프리팹 루트에 있었음
    - **해결 방법:** `GetComponent` → `GetComponentInChildren`으로 변경

    **🧠 내가 이해한 원리:**
    `CharacterSpawner.SpawnVisual`에서 `Instantiate(prefab, characterModelRoot)`로 비주얼을 `characterModelRoot`의 **자식**으로 생성함. 이후 `CacheRenderers(characterModelRoot)`를 호출하므로 `modelRoot`는 빈 부모 오브젝트. `GetComponent`는 자신만 탐색하고 자식은 탐색하지 않으므로, 자식에 붙은 컴포넌트는 반드시 `GetComponentInChildren`을 써야 함.
    
    **교훈:** 컴포넌트 부착 위치를 안내하기 전에 Spawner/초기화 코드에서 어떤 Transform이 전달되는지 먼저 확인할 것.

### 💻 주요 코드 스니펫

**🔹 목적: 셰이더 분기 처리**

```csharp
// PlayerBushState.cs
public static Material CreateFadeMaterial(Material src, float alpha, ShaderFadeProfile profile = null)
{
    var mat = new Material(src);

    if (profile != null && profile.type == ShaderFadeType.PropertyValue)
    {
        if (mat.HasProperty(profile.propertyName))
            mat.SetFloat(profile.propertyName, profile.fadeValue);

        mat.SetInt("_SrcBlend", (int)BlendMode.SrcAlpha);
        mat.SetInt("_DstBlend", (int)BlendMode.OneMinusSrcAlpha);
        mat.SetInt("_ZWrite",   0);
        mat.renderQueue = (int)RenderQueue.Transparent;
        // additionalProperties 루프
    }
    else
    {
        // URP(_Surface) → Standard(_Mode) → Fallback 순서
    }
    return mat;
}
```

📌 **사용 이유:** Material 인스턴스를 미리 만들어 두고 `r.materials = _fadeMats[i]`로 교체. `sharedMaterials`를 직접 수정하면 모든 인스턴스에 영향을 줌.

📌 **주의할 점:** `_ZTest = Always`를 추가로 설정해 부쉬 메쉬에 가려져도 캐릭터가 보이도록 처리됨.

## 4️⃣ 부쉬 즉시 투명 (클라이언트 선행 처리)

### ✅ 결과

로컬 플레이어가 부쉬에 들어가면 서버 딜레이(0.5초) 없이 즉시 부쉬 메쉬 반투명 전환

### 📌 수행 이유

서버에서 `inBush=true` SyncVar가 오기까지 0.5초 딜레이가 있음. 이 동안 내가 부쉬 안에 있는데 메쉬가 불투명하면 시각적으로 어색함.

### 📝 작업 내용

- `BushZone.OnTriggerEnter` — `if (isClient)` 블록에서 로컬 플레이어 진입 시 `SetLocalPlayerInside(true)` 즉시 호출
- `BushZone.OnTriggerExit` — 동일하게 즉시 복원
- 서버의 `inBush` SyncVar는 게임플레이 판정용(숨김/노출), 클라이언트 즉시 처리는 시각 피드백 전용으로 역할 분리

### 💻 주요 코드 스니펫

**🔹 목적: 클라이언트 즉시 시각 처리 vs 서버 판정 분리**

```csharp
// BushZone.cs
private void OnTriggerEnter(Collider other)
{
    // 클라이언트: 로컬 플레이어 진입 시 부쉬 즉시 반투명 (서버 딜레이 없이)
    if (isClient)
    {
        var localBushState = other.transform.root.GetComponent<PlayerBushState>();
        if (localBushState != null && localBushState.isLocalPlayer)
            SetLocalPlayerInside(true);
    }

    if (!isServer) return;
    // ... 서버 판정 로직
}
```

📌 **사용 이유:** 게임플레이 판정(숨김 여부)은 서버가 권위를 가지지만, 시각 피드백은 로컬에서 선행 처리해 반응성을 높임. 브롤스타즈와 동일한 방식.

📌 **주의할 점:** 서버 전용 호스트에서는 `isClient`와 `isServer`가 동시에 true이므로 두 블록 모두 실행됨. 문제 없음.

## 5️⃣ HP바 부쉬 반투명

### ✅ 결과

부쉬 안에서 보이는 플레이어의 HP바가 캐릭터와 동일하게 반투명 처리됨

### 📌 수행 이유

캐릭터는 반투명인데 HP바는 불투명이면 시각적으로 어색함. 일관된 UX.

### 📝 작업 내용

- `PlayerHPBar`에 `CanvasGroup` 캐싱 추가 (없으면 `AddComponent`)
- `SetBushVisible(bool visible, bool fade = false)` — fade=true면 `bushAlpha`(기본 0.4f) 적용
- `PlayerBushState.SetVisible` — `_hpBar?.SetBushVisible(visible, fade)` 로 fade 값 전달

### 💻 주요 코드 스니펫

**🔹 목적: Canvas 전체 알파 제어**

```csharp
// PlayerHPBar.cs
public void SetBushVisible(bool visible, bool fade = false)
{
    if (hpCanvasTransform != null)
        hpCanvasTransform.gameObject.SetActive(visible);

    if (_canvasGroup != null)
        _canvasGroup.alpha = (visible && fade) ? bushAlpha : 1f;
}
```

📌 **사용 이유:** `CanvasGroup.alpha`는 자식 UI 전체에 일괄 적용되므로 Slider, Image 개별 처리 불필요.

📌 **주의할 점:** `CanvasGroup`이 없으면 Start에서 `AddComponent`로 자동 추가. 프리팹에 미리 붙여두면 런타임 AddComponent 비용 절약.

## 🧠 오늘 배운 점

- `GetComponent`는 자신만, `GetComponentInChildren`은 자신+자식 탐색. 계층 구조 파악 없이 쓰면 항상 null 위험
- Spawner에서 전달하는 Transform이 어느 오브젝트인지 코드로 먼저 확인한 뒤 컴포넌트 부착 위치를 결정해야 함
- 셰이더 투명 처리는 renderQueue, ZWrite, BlendMode를 함께 세팅해야 동작. 하나만 빠져도 안 됨
- 클라이언트 즉시 피드백 vs 서버 권위 판정을 분리하면 체감 반응성 향상 (시각=클라이언트 선행, 판정=서버)
- `CanvasGroup.alpha`로 UI 계층 전체 알파를 한 번에 제어 가능 — 개별 Image 색상 변경보다 훨씬 간단
