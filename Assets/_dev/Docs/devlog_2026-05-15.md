## 1️⃣ 모바일 로컬 테스트 환경 구축

### ✅ 결과

`ServerConfig.cs` 파일 하나만 바꾸면 로컬 IP / 배포 서버를 전환할 수 있는 구조 완성

### 📌 수행 이유

로컬 PC에서 게임서버를 돌리고 같은 WiFi 모바일에서 테스트하려면, 클라이언트가 `127.0.0.1` 대신 PC의 로컬 IP로 접속해야 함

### 📝 작업 내용

- `ServerConfig.cs` 생성 — `GameServerIP`, `LobbyPort`, `BattlePortBase` 상수 관리
- `LoginController`, `CustomNetworkManager` 세 곳의 `"127.0.0.1"` 하드코딩을 `ServerConfig.GameServerIP`로 교체
- `StartBattleConnect(string ip, ushort port)` 버그 수정 — 파라미터를 받아놓고 내부에서 `"127.0.0.1":7778`을 하드코딩하던 문제 제거

### ⚠️ 트러블슈팅

- **문제 :** 방화벽 규칙 추가 명령이 적용 안 됨
    - **원인 :** PowerShell을 일반 권한으로 실행해서 `New-NetFirewallRule`이 실패
    - **해결 방법 :** 관리자 권한 PowerShell에서 재실행

    **🧠 내가 이해한 원리 :**
    Windows 방화벽 규칙 변경은 관리자 권한 필수. 일반 권한에선 명령이 실패해도 오류 없이 넘어갈 수 있음

- **문제 :** 방화벽 열었는데도 모바일 접속 불가
    - **원인 :** PC가 유선(이더넷), 모바일이 무선(WiFi)일 때 공유기 AP 격리(Client Isolation) 설정이 둘 사이 통신 차단
    - **해결 방법 :** 공유기 관리 페이지에서 AP 격리 옵션 확인 필요

    **🧠 내가 이해한 원리 :**
    같은 공유기라도 유선↔무선 간 통신을 막는 AP 격리 기능이 있음. `adb shell ping`으로 먼저 기본 연결부터 확인하면 원인 빠르게 파악 가능

### 💻 주요 코드 스니펫

**🔹 목적: IP 설정 중앙화**

```csharp
public static class ServerConfig
{
    public const string GameServerIP   = "192.168.1.39"; // 로컬 테스트용
    public const ushort LobbyPort      = 7777;
    public const ushort BattlePortBase = 7778;
}
```

📌 **사용 이유 :** IP가 바뀔 때 이 파일 하나만 수정하면 됨
📌 **주의할 점 :** 배포 시 반드시 공인 서버 IP로 교체

## 2️⃣ 서버 연결 실패 시 무한 로딩 버그 수정

### ✅ 결과

연결 실패 시 5초 타임아웃 후 로그인씬으로 자동 복귀

### 📌 수행 이유

서버 접속 실패 시 로딩 바가 90%에서 영원히 멈추는 문제 발생

### 📝 작업 내용

`LoadingSceneManager.cs`의 서버 연결 대기 루프 수정

### ⚠️ 트러블슈팅

- **문제 :** 로딩이 90%에서 멈춤
    - **원인 :** `while (!NetworkClient.isConnected || timer < minDuration)` — `||` 조건으로 연결 실패 시 루프가 절대 종료되지 않음
    - **해결 방법 :** `&&`로 변경하고 5초 타임아웃 + 실패 처리 추가

    **🧠 내가 이해한 원리 :**
    `A || B` : A가 true면 B 관계없이 계속 → 연결 실패(A=true)면 무한루프
    `A && B` : 둘 다 true여야 계속 → 5초 지나면(B=false) 자동 탈출

### 💻 주요 코드 스니펫

**🔹 목적: 연결 실패 타임아웃 처리**

```csharp
const float connectTimeout = 5f;
while (!NetworkClient.isConnected && timer < connectTimeout)
{
    yield return null;
    timer += Time.deltaTime;
    ...
}

if (!NetworkClient.isConnected)
{
    Debug.LogError($"[LOADING] 서버 연결 실패: {req.serverAddress}:{req.port}");
    NetworkClient.Disconnect();
    SceneManager.LoadScene("LoginScene");
    yield break;
}
```

📌 **사용 이유 :** 연결 불가 상황에서 플레이어가 무한 대기하지 않도록
📌 **주의할 점 :** `yield break` 없으면 이후 코드(Ready/AddPlayer)까지 실행됨

## 3️⃣ 팀 인디케이터 데칼 구현

### ✅ 결과

캐릭터 발 아래 파스텔 톤 링 데칼 표시 (자신=민트 초록 / 아군=하늘 파랑 / 적군=코랄 빨강)
부쉬 안 적군은 인디케이터도 함께 숨김, 사망 시 자동으로 사라짐

### 📌 수행 이유

아군과 적군의 시각적 구분이 어려워 브롤스타즈식 하단 데칼 도입

### 📝 작업 내용

- `TeamIndicator.cs` 컴포넌트 신규 작성
- 도넛(링) 형태 메시 직접 생성 — 안쪽 링(alpha=0) + 바깥 링(alpha=1) 버텍스 컬러 그라데이션
- `Sprites/Default` 셰이더 사용 — URP 포함 모든 파이프라인에서 동작
- `PlayerBushState`의 `inBush`, `isRevealed`, `currentBushIdentity` SyncVar를 LateUpdate에서 체크해 부쉬 연동
- `PlayerStats.RpcOnDeath()`에서 `Hide()` 호출, `LateUpdate`에서 `IsDead` 추가 체크

### ⚠️ 트러블슈팅

- **문제 :** 전부 핑크색으로 표시됨
    - **원인 :** `Shader.Find("Unlit/Color")`가 URP에서 반환 null → 핑크(에러 머티리얼)
    - **해결 방법 :** `Sprites/Default` 셰이더로 교체 (버텍스 컬러 지원 + URP 호환)

- **문제 :** 링 모양이 아니라 채워진 원으로 나옴
    - **원인 :** 중심점(alpha=0) → 가장자리(alpha=1) 구조라 안쪽이 흐릿하게 보임
    - **해결 방법 :** 안쪽 링(alpha=0) + 바깥 링(alpha=1) 도넛 메시로 변경

- **문제 :** `Hide()` 호출해도 데칼이 사라지지 않음
    - **원인 :** `LateUpdate`에서 매 프레임 `_root.SetActive(IsVisibleToLocal())`로 덮어씌움
    - **해결 방법 :** `LateUpdate` 최상단에서 `_stats.IsDead` 먼저 체크

    **🧠 내가 이해한 원리 :**
    `LateUpdate`는 매 프레임 실행되므로, 외부에서 SetActive를 꺼도 다음 프레임에 덮어씌워짐. 상태 플래그를 LateUpdate 안에서 직접 판단해야 함

### 💻 주요 코드 스니펫

**🔹 목적: 도넛 메시 생성 (버텍스 컬러 그라데이션)**

```csharp
// 안쪽 링: alpha=0 (투명), 바깥 링: alpha=1 (불투명)
for (int i = 0; i < segments; i++)
{
    float a = i * (2f * Mathf.PI / segments);
    verts[i]         = new Vector3(Mathf.Cos(a) * innerR, 0f, Mathf.Sin(a) * innerR);
    colors[i]        = new Color(r, g, b, 0f); // 안쪽: 투명

    verts[i+segments]  = new Vector3(Mathf.Cos(a) * radius, 0f, Mathf.Sin(a) * radius);
    colors[i+segments] = new Color(r, g, b, 1f); // 바깥: 불투명
}
```

📌 **사용 이유 :** 별도 셰이더 없이 버텍스 컬러만으로 자연스러운 그라데이션 구현
📌 **주의할 점 :** `Sprites/Default`는 버텍스 COLOR 시맨틱을 읽음. `mesh.colors` 배열이 반드시 세팅돼야 함

## 4️⃣ 북쪽팀 PC 스킬 방향 반전 버그 수정

### ✅ 결과

PC에서 북쪽팀 플레이어의 스킬이 마우스 방향으로 정상 발사됨

### 📌 수행 이유

팀1(북쪽) PC 플레이어가 마우스 오른쪽을 클릭해도 스킬이 왼쪽으로 나가는 버그

### 📝 작업 내용

- `PlayerCombat`에 `_useMobileAimSign` 플래그 + `SetInputMode(bool)` 메서드 추가
- `PlayerController.OnStartLocalPlayer()`에서 입력 모드(PC/모바일) 주입
- `ToAimDir3D()`에서 모바일일 때만 aimSign 적용

### ⚠️ 트러블슈팅

- **문제 :** PC 마우스 방향이 팀1에서 반전
    - **원인 :** `GetMouseAimDir()`은 이미 월드스페이스 방향(마우스위치 - 캐릭터위치)을 반환하는데, `ToAimDir3D()`가 팀1에서 `aimSign=-1`을 추가로 곱해서 이중 반전 발생
    - **해결 방법 :** aimSign은 모바일 조이스틱(스크린 상대 방향)에만 필요. PC 마우스는 이미 월드스페이스이므로 적용 제외

    **🧠 내가 이해한 원리 :**
    팀1 반전 보정은 조이스틱 입력이 카메라 기준 상대좌표이기 때문에 필요한 것. 마우스 입력은 레이캐스트로 월드좌표를 직접 구하므로 추가 보정 불필요

### 💻 주요 코드 스니펫

**🔹 목적: 입력 방식에 따라 aimSign 선택 적용**

```csharp
// PlayerController에서 주입
_combat.SetInputMode(useMobile);

// PlayerCombat.ToAimDir3D
private Vector3 ToAimDir3D(Vector2 dir2D)
{
    float s = _useMobileAimSign ? GetAimSign() : 1f;
    return new Vector3(dir2D.x * s, 0f, dir2D.y * s).normalized;
}
```

📌 **사용 이유 :** 입력 소스(PC/모바일)를 PlayerCombat이 직접 판단하지 않고, PlayerController가 주입하는 방식으로 결합도 낮춤
📌 **주의할 점 :** 에디터에서는 `useMobile = true`로 강제되므로 에디터 테스트 시 모바일 입력 기준으로 동작함

## 🧠 오늘 배운 점

- 로컬 멀티 테스트 시 방화벽 + AP 격리 두 가지를 모두 확인해야 함. `adb shell ping`으로 기본 연결부터 검증하면 원인 파악이 빠름
- `LateUpdate`에서 `SetActive`를 매 프레임 갱신하는 구조라면, 외부에서 한 번 끄는 방식은 동작하지 않음. 상태 플래그를 LateUpdate 안에서 직접 판단해야 함
- `Shader.Find()`는 셰이더가 프로젝트에 실제로 포함되어 있어야 작동. URP에서는 빌트인 셰이더명이 다르므로 `Sprites/Default` 같이 범용적인 것을 사용하거나 사전에 셰이더 존재 여부를 확인해야 함
- aimSign 보정은 입력 좌표계가 스크린 상대인지 월드 절대인지에 따라 달라짐. 월드좌표로 들어오는 PC 마우스에 보정을 추가 적용하면 이중 반전 발생
