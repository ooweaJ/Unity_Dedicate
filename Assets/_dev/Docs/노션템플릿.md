● 터널링 문제와 해결 원리

1. 왜 벽을 뚫었나 — 터널링
Unity Physics는 이산(Discrete) 감지 방식입니다. 매 FixedUpdate마다 "지금 이 위치에서 다른 콜라이더와 겹치는가?"만 체크합니다.

프레임 N    프레임 N+1
[투사체]→→→→→[벽]→→→→[투사체]
↑
이 사이를 순간이동

투사체는 rb.MovePosition()으로 순간이동합니다. 이동 거리가 15 × 0.02 = 0.3 유닛/프레임인데 벽이 그보다 얇으면, N프레임엔 벽 앞, N+1프레임엔 벽 뒤 — 한 번도 겹친 적 없으니 OnTriggerEnter가 발생하지 않습니다.

---

1. SphereCast가 뭔가

Physics.SphereCast는 구체를 특정 방향으로 쭉 밀었을 때 뭔가에 닿는지 미리 계산합니다. 실제로 이동하지 않고, 경로만 검사합니다.

[투사체(구체)]──────────────────────────────→
이 경로 위에 뭔가 있어?

공식처럼 이해하면:

- RayCast = 점이 직선으로 날아감
- SphereCast = 구체가 직선으로 날아감 (두께 있는 레이캐스트)

투사체가 구체 콜라이더니까 SphereCast를 써야 가장자리 충돌도 정확하게 잡힙니다.

---

1. 기존 코드 vs 수정 코드 흐름

기존 (OnTriggerEnter 방식):
FixedUpdate → rb.MovePosition(목적지로 이동)
↓
[물리엔진이 겹침 감지하면]
↓
OnTriggerEnter → Bounce()
문제: 이동 먼저, 감지는 나중. 벽이 얇으면 이미 통과.

수정 (SphereCast 방식):
FixedUpdate → SphereCast(이동 경로 미리 조사)
↓               ↓
벽 감지됨         감지 없음
↓               ↓
벽 앞까지만 이동   원래대로 이동
→ 반사 계산
이동 전에 경로를 검사하므로 속도에 상관없이 벽을 놓치지 않습니다.

---

1. 법선(Normal)이 왜 중요한가

반사 공식은 Vector3.Reflect(입사방향, 법선)입니다.

```
      법선(↑)
```

벽 ─────────────
\   ↑   /
\  │  /
\ │ /
입사→ \│/ ←반사

법선이 틀리면 반사 방향이 완전히 이상해집니다. 기존 ClosestPoint 방식의 문제:

// 투사체가 트리거 내부에 있을 때
Vector3 closest = wallCollider.ClosestPoint(transform.position);
// Unity 스펙: 점이 내부에 있으면 closest = transform.position 그대로 반환
Vector3 normal = (transform.position - closest).normalized;
// → (pos - pos) = Vector3.zero → 법선이 0벡터
// → Reflect(dir, zero) = zero → 투사체 멈춤

SphereCast는 충돌 시 RaycastHit.normal을 직접 줍니다. 이건 물리엔진이 계산한 정확한 벽 표면 법선이라 별도 계산이 필요 없습니다.

---

1. QueryTriggerInteraction.Collide 파라미터

Physics.SphereCast(..., wallLayer, QueryTriggerInteraction.Collide)

SphereCast는 기본적으로 트리거 콜라이더를 무시합니다. 벽이 트리거로 설정돼 있어도 감지하려면 이 옵션이 필요합니다.
