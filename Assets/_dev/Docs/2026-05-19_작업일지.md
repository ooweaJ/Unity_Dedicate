public static int GoldCalculate(PlayerResultData data, bool isDraw)

## 2️⃣ 강화 UI 재강화 불가 버그 수정

### ✅ 결과

강화 후 애니메이션이 끝나면 메세지가 표시되고, 0.8초 후 자동으로 preview를 재요청해 버튼이 다시 활성화됨.

### 📌 수행 이유

강화 성공/실패 후 결과 아이콘 색상이 고정되면서 버튼 `interactable = false`로 끝나버려, 패널을 닫았다가 다시 열어야만 재강화가 가능했음.

### 📝 작업 내용

**흐름 변경**

| 단계 | 기존 | 수정 |
|---|---|---|
| 서버 응답 직후 | MessagePanel 즉시 표시 | 애니메이션 재생 |
| 애니메이션 종료 | 버튼 비활성화 고정 | 색 고정 → MessagePanel 표시 |
| 0.8초 후 | (아무것도 없음) | loading 상태 → preview 재요청 → 버튼 재활성화 |

**수정 파일**

| 파일 | 변경 내용 |
|---|---|
| `EnhancePanel.cs` | `OnResultReady(bool, int)` 이벤트 추가 (색 고정 직후 발생), `OnResultAnimComplete(int)` 이벤트 추가 (0.8초 후 발생) |
| `InventoryUIManager.cs` | 두 이벤트 구독, `ShowEnhanceResult`에서 MessagePanel 호출 제거 → `HandleEnhanceResultReady`로 분리 |

### ⚠️ 트러블슈팅

- **문제 :** 강화 후 버튼이 영구 비활성화 상태로 남음
    - **원인 :** `ShowResultAfterMinDuration` 코루틴 마지막에 `enhanceButton.interactable = false`로 끝나고, 이후 preview 재요청이 전혀 없었음
    - **해결 방법 :** 코루틴 끝에서 이벤트를 발생시켜 `InventoryController`가 `HandleEnhancePreview`를 다시 호출하도록 연결

    **🧠 내가 이해한 원리 :**

    Unity UI의 버튼 활성화는 상태 머신이 아니라 단순 플래그임. 누군가 명시적으로 `interactable = true`를 다시 호출해줘야 하므로, "결과 애니메이션 완료" 시점을 이벤트로 외부에 알려주는 구조가 필요.

### 💻 주요 코드 스니펫

**🔹 목적: 애니메이션 완료 후 이벤트로 UI 갱신 흐름 제어**

```csharp
private IEnumerator ShowResultAfterMinDuration(bool success, int enhance)
{
    // ... minAnimDuration 대기 ...

    // 색 고정 → 메세지 표시 트리거
    OnResultReady?.Invoke(success, enhance);

    // 0.8초 노출 후 loading 상태로 전환 → preview 재요청
    yield return new WaitForSeconds(0.8f);
    SetLoadingState();
    OnResultAnimComplete?.Invoke(_equipInstanceId);
}
```

📌 **사용 이유 :** 패널 내부 타이밍(코루틴)과 외부 비즈니스 로직(preview 재요청)을 이벤트로 분리해 단방향 의존성 유지

📌 **주의할 점 :** `OnResultAnimComplete` → `OnEnhancePreviewRequested` → `HandleEnhancePreview` (서버 호출) 순으로 체인됨. 최대강화 상태면 서버가 `maxEnhance: true` 반환 → 버튼 자동 비활성화되므로 별도 처리 불필요

## 🧠 오늘 배운 점

- Unity UI 버튼은 상태 머신이 아니라 플래그 — `interactable = false`로 끝내면 아무도 안 켜줌. 흐름의 끝에서 반드시 재활성화 트리거를 명시해야 함
- 코루틴 내부 타이밍을 외부에 알릴 때 이벤트가 가장 깔끔한 해법. 코루틴이 직접 외부 메서드를 호출하면 의존성이 역전됨
- 트랜잭션 안에서 여러 컬럼을 동시에 UPDATE하면 레이스 컨디션 없이 정합성 보장 가능
